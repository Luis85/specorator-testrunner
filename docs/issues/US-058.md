# US-058 Flakiness score & quarantine

## User Story

As a **QA Engineer**, I want scenarios flagged flaky (status flips,
retry-passes) and a quarantine workflow with owner and fix-by date, so that
flakiness is managed instead of eroding trust.

## Acceptance Criteria

- Stability score per scenario over the history window
- `@quarantine` tag excludes from KPI (like `@wip`) but still runs
- Quarantine note records owner + deadline
- Dashboard shows quarantined count and oldest deadline
- Quarantined >cap (default 5% of scenarios) raises a warning

## Progress

- **Slice 1 — flakiness scoring projection (in progress):** the foundational
  "stability score per scenario over the history window" AC. Pure domain
  projection `computeFlakiness` (pass↔fail flip rate + classification bands) over
  the US-057 history window, exposed via `ScenarioHistoryService.flakiness()`.
  Design: [US-058 flakiness scoring](../superpowers/specs/2026-06-17-us-058-flakiness-scoring-design.md).
- **Still to do:** `@quarantine` tag (exclude from KPI like `@wip`, still runs);
  quarantine note recording owner + fix-by deadline; dashboard quarantined count
  & oldest deadline; cap warning (default 5%); retry-pass signal via the Cucumber
  Messages parser.
