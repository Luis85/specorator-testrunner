# US-090 Runner transparency — show the files behind a Use Case

As a **Developer**, I want the Use Case and Feature detail views to show
which technical artifacts sit behind what I see in Obsidian — the matched
step-definition files, page objects, support files, and the `.testrunner`
layout — so that I understand what is actually under the hood without
reverse-engineering the generated project in an external IDE.

Source: 1.0.0 release-validation feedback (PR #33) — "I just saw the
use-case and feature inside Obsidian but I have no clue what's under the
hood, so what is technically behind, what files."

## Acceptance Criteria

- The Use Case detail view gains a "Behind this Use Case" section listing
  the Feature file path(s), the step-definition files whose steps the
  scenarios matched, and the support/page-object files they import
- Each listed file offers an "Open" action (system default editor or
  Obsidian where the file type allows); paths are copyable
- A "Runner layout" explainer (generated docs and/or a dashboard link)
  documents the `.testrunner` structure: `src/steps/`, `src/pages/`,
  `src/support/`, `cucumber.mjs`, `reports/`
- Stretch (may split into its own story): read-only inline code view of a
  step definition from the detail view; full inline *editing* is explicitly
  out of scope here — it builds on the Step Library index ([[US-081]]) and
  the editor foundations, and deserves its own story when prioritized
