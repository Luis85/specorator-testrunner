# US-090 Visual regression steps

## User Story

As a **QA Engineer**, I want an opt-in library of visual-comparison steps
backed by `toHaveScreenshot`, with baselines stored in the vault, so that
visual regressions fail the suite with a reviewable diff instead of slipping
to production.

## Acceptance Criteria

- Opt-in step library: installing it is an explicit action, never part of
  the default `.testrunner`
- Baselines live under the configured evidence folder (git-versioned visual
  evidence), organized per scenario and per Playwright project (browser)
- Comparison tolerances (`maxDiffPixels` / `maxDiffPixelRatio`) are
  configurable per step and default to values that avoid the documented
  false-positive trap
- A failing comparison attaches expected/actual/diff images to the Evidence
  note
- Updating a baseline is an explicit, confirmable action — never automatic
  on failure
