# US-098 Story Map artifact + builder

## User Story

As a **Product Owner**, I want a Story Map artifact that shapes the product
journey — an ordered backbone of activities and release slices over the Use
Cases (referenced by id) — so that I can sequence the work and plan a walking
skeleton across PRDs without leaving the vault.

## Acceptance Criteria

- A `type: story-map` note (`SM-NNN`) stored one folder per map under
  `Story Maps/`, anchored to a product (a PRD id), with parser-safe flat
  frontmatter (`activities`, `slices`, `cards`) — Bases-queryable (per
  ADR-0027).
- A builder wizard (title + product → backbone → slices → review) and a
  "New Story Map" command + ribbon.
- A live **Story Maps** explorer that lists maps with their backbone/slice/
  card counts and offers open, rebuild-grid, and delete.
- The note body renders a slices × activities grid whose cells are resolved,
  aliased Use Case links (`[[<note name>\|UC-NNN]]`), regenerable from the
  authoritative `cards` frontmatter via **Rebuild grid** without clobbering
  hand-written sections.
- `storymap.created` / `storymap.deleted` domain events; service + pure
  projections unit-tested.

## Out of scope (follow-ups)

- A drag-drop / in-modal grid editor for placing cards (the proposal defers
  card placement to note-editing + rebuild; a structured detail editor is a
  later story).
- A dangling-reference lint flagging cards that point at deleted/deprecated
  Use Cases (ADR-0027 consequence; layer on the EPIC-017 §9 validation work).
- storymaps.io YAML import/export interop.
