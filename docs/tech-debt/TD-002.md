# TD-002 Enforce the one-argument-per-step rule in the domain model

> Gherkin allows a step at most ONE argument (a data table OR a doc string).
> Today that invariant is enforced only at the UI surface, not where the data
> lives.

## Current state

- `GherkinStep` (`src/domain/entities/specification.ts`) permits `dataTable`
  and `docString` simultaneously.
- The Feature Editor gates its add-buttons so a step can only gain one
  argument (`feature-editor-view.ts`, `renderStepExtras`).
- `projectValidation` (`feature-editor-format.ts`, `flagDoubleArguments`)
  flags steps that arrive with both as an error.
- `serialiseFeature` happily writes both, producing Gherkin Cucumber refuses
  to parse.

## Cost

Any non-view producer of a `GherkinStep` bypasses the protection: a raw-mode
edit (or external tool) that hand-writes a step with both arguments parses
fine — the lenient parser attaches both to the same step — round-trips, and
serialises back to invalid Gherkin. The only safety net is the validation
strip, which the user can ignore.

## Proposed direction

Move the invariant to the model/serialize boundary. Options, in order of
depth:

1. **Sum type:** `argument?: { kind: "table"; rows: string[][] } | { kind: "docString"; … }`
   on `GherkinStep` — makes the invalid state unrepresentable. Touches the
   parser, serializer, view, validation, and all step-construction sites.
2. **Serialize-time rule:** `serialiseFeature` emits only one argument
   (table wins, doc string dropped) and the round-trip guard then fails for
   both-argument files, forcing raw mode — cheaper, keeps the type loose.

Option 1 is the right depth; option 2 is an acceptable stopgap. Either way the
`flagDoubleArguments` validation stays as the user-facing explanation.

## Resolution (2026-06-12)

Resolved in the pre-V2 Phase 1 increment (plan:
`docs/superpowers/plans/2026-06-12-pre-v2-phase-1-clear-recorded-debt.md`)
via option 1 (sum type): `GherkinStep.argument` is
`{ kind: "table" } | { kind: "docString" }`, so a step with both arguments is
unrepresentable; the parser keeps the FIRST argument (a conflicting later one
is dropped and the round-trip guard sends the file to raw mode, mirroring
Cucumber's rejection); `flagDoubleArguments` and its validation message are
deleted along with the editor's two-condition button gating.
