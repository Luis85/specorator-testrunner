# TD-004 Replace the Feature Editor's `commit(structureChanged)` flag

> Every edit handler in the Feature Editor must hand-classify its change as
> structural (full re-render) or field-level (validation refresh only). The
> classification is correctness-critical and unverifiable by unit tests.

## Current state

`FeatureEditorView.commit(structureChanged: boolean)`
(`src/presentation/views/feature-editor-view.ts`) re-serialises and schedules
a save on every call; the boolean decides between `render()` (rebuilds the
whole DOM, steals focus) and `refreshValidation()` (leaves the DOM alone).
~29 call sites each pass the flag by hand. The `false` path exists precisely
because a full re-render steals focus from the input being edited.

## Cost

Any new edit handler that mutates structure but passes `commit(false)` ships
a stale-DOM bug; the reverse steals focus mid-typing. These bugs live only in
the view wiring, which is untested by convention — the pure-helper tests
cannot catch them. The review found one instance already (the Examples
column-rename handler, fixed in the polishing pass), and every future control
re-rolls the dice.

## Proposed direction

Make re-rendering safe instead of avoidable: always re-render on commit and
restore focus/caret afterwards (track the focused element by a stable key —
e.g. `data-path` attributes like `scenario:2/step:1/text` — and re-focus
after rebuild), or adopt keyed DOM reconciliation for the editor body. Then
`commit()` loses its parameter and the per-call-site classification burden
disappears.

A second-order benefit: the full-DOM-teardown cost per keystroke goes away as
a design concern because re-render frequency becomes uniform and optimisable
in one place.

## Resolution (2026-06-12)

Resolved in the pre-V2 Phase 1 increment (plan:
`docs/superpowers/plans/2026-06-12-pre-v2-phase-1-clear-recorded-debt.md`)
via the always-re-render direction: `commit()` lost its `structureChanged`
parameter; every commit re-renders and restores focus/caret through stable
positional `data-focus-key` attributes (`captureFocus`/`restoreFocus` in
`src/presentation/views/focus-restore.ts`). The ~30 call sites no longer
hand-classify changes, so the stale-DOM / focus-steal failure mode is gone
by construction; re-render cost is uniform and optimisable in one place
(commits fire on `change` events, not per keystroke). V2's editor growth
(US-074 lint strip, US-081 autocomplete, US-082 Use Case Editor) builds on
the safe-by-construction pattern.
