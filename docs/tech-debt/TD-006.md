# TD-006 Flip the advisory quality gates to blocking and tighten them

> The fallow audit and the remaining warn-level lint rules report quality
> problems but cannot fail a build. Advisory was the deliberate launch
> posture; gating is the recorded follow-up.

## Current state

- The `quality` job in `.github/workflows/ci.yml` runs `fallow audit` with
  `continue-on-error: true` — a warn/fail verdict marks the step failed for
  visibility but never blocks the PR. The job comment and the
  [fallow integration design spec](../superpowers/specs/2026-06-11-fallow-integration-design.md)
  both record gating as the intended follow-up "once signal quality is
  observed on a few PRs."
- `eslint.config.mjs` still carries warn-level rules
  (`vitest/no-disabled-tests`), which `npm run lint` reports without failing.
- `.fallowrc.jsonc` thresholds are the launch defaults; they have not yet
  been tuned against real PR verdicts.

## Cost

Advisory findings rot: once contributors learn the job cannot fail, the
verdict in the step summary stops being read, and regressions (dead code,
duplication, complexity spikes, disabled tests) accumulate silently. The
longer the flip is deferred, the larger the first red build becomes — and if
V2 feature work starts before the flip, every threshold negotiation happens
under feature pressure against code that was written to the lenient bar
(see the V2 proposal §9 item 0.4, which sequences this before any V2 scope).

## Proposed direction

After signal quality has been observed on a few PRs:

1. Tune `.fallowrc.jsonc` thresholds to the repo's real baseline so the gate
   fails on regressions, not on the existing inventory.
2. Remove `continue-on-error: true` from the audit step and update the job
   comment (the verdict becomes a required check).
3. Promote the remaining warn-level lint rules to errors
   (`vitest/no-disabled-tests` — recheck for others at flip time) and fix or
   explicitly suppress the findings they surface.
4. Record the flip in CHANGELOG.md and close this item with the PR link.

## Resolution (2026-06-12)

Resolved by PR #33 (commit `d6b1c9e`), the pre-V2 Phase 0 increment (plan:

1. Thresholds: verified the audit gates with new-only attribution
   (the audit runs in fallow's default `new-only` gate mode; current verdict `pass`) — it already fails on
   regressions, not inventory, so the launch defaults stand (decision
   recorded in `.fallowrc.jsonc`).
2. `continue-on-error` removed from the audit step; the quality job is a
   blocking check.
3. `vitest/no-disabled-tests` promoted to error (zero findings at flip time;
   no other warn-level rules remained).
4. Recorded in CHANGELOG under the V1 release.
