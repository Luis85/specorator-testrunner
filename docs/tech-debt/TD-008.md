# TD-008 Stale cucumber-js comments deferred in fallow-flagged files

> The cucumber-js → playwright-bdd comment sweep (PR #48) was applied to
> gate-clean files only; 10 files were reverted because comment-only edits
> pull a touched file's PRE-EXISTING fallow findings into the blocking audit.

## Current state

PR #48 swept stale `cucumber-js` runtime references out of the architecture
docs and source comments. The source half stopped short in 10 files: editing
them (even comment-only) brings their pre-existing fallow findings into the
blocking `quality` gate's scope (the documented footgun, `ci.yml:61` / TD-006),
so the sweep was reverted there to keep CI green.

The deferred files still carry stale "Cucumber" runtime wording, each blocked by
a pre-existing finding:

| File | Pre-existing finding that pulls it into the gate |
| --- | --- |
| `domain/policies/command-safety-policy.ts` | `assertSafe` complexity (cyclomatic 25, cognitive 33) |
| `application/services/test-execution-service.ts` | `tokenizeCommand` complexity (cognitive 23) + clone with `runner-installation-service` |
| `presentation/views/feature-editor-view.ts` | CRAP on `refreshValidation`/`populateDatalists`/`renderScenarioCard`, 7 false-positive "unused" Obsidian API methods, two internal clones |
| `presentation/views/create-suite-modal.ts` | `submit` CRAP + clones with `create-use-case-modal` |
| `application/content/gherkin.ts` + `presentation/views/feature-editor-format.ts` | the 213-line clone (see [[TD-007]]) |
| `application/services/feature-insight-service.ts` | two clones (one with `specification-service`) |
| `application/services/suite-service.ts` | clone with `use-case-service` |
| `infrastructure/runner/node-child-process-runner.ts` | `disposeAll` false-positive "unused" finding |
| `domain/onboarding/tour-steps.ts` | internal 20-line clone |

## Why it was deferred

Reducing `assertSafe` / `tokenizeCommand` complexity or extracting the clones is
real refactoring, out of scope for a comment sweep — and `assertSafe` is the
command-injection guard (P0-1 / SEC-1), where churn carries security risk. The 8
"unused class member" findings are FALSE POSITIVES: required Obsidian
`TextFileView`/lifecycle overrides (`getViewType`, `setViewData`, `disposeAll`,
…) that cannot be removed; clearing them needs `fallow-ignore` annotations, not
deletion.

## Cost

Those 10 files keep stale "Cucumber" runtime comments (the `npm → node →
Cucumber` process-tree wording, the suite `--tags` mechanism, the `cucumber.mjs`
glob references) until revisited. Every future edit to them keeps tripping the
audit on the same inherited findings.

## Intended direction

A focused refactor increment that:

1. decomposes `assertSafe` / `tokenizeCommand` below the complexity thresholds
   and extracts the duplicated blocks (coordinate with [[TD-007]] for the
   `gherkin.ts` ↔ `feature-editor-format.ts` clone);
2. adds `fallow-ignore` annotations for the false-positive Obsidian API "dead
   code" so the gate stops counting them; then
3. re-applies the `cucumber-js` → `playwright-bdd` comment cleanup in the 10
   files (the runtime is `bddgen` + `playwright test`; the cucumber-JSON report
   format stays).
