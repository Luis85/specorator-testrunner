# UC-006 Generate Feature Specification

> Generate a Gherkin specification from a Use Case.

- **Domain:** Specifications
- **Primary Actor:** Business Analyst
- **Scope:** Mandatory MVP
- **Owning Service:** `FeatureAggregate` (see [Solution Design §10](../architecture/Solution%20Design.md))

## Main Success Scenario

1. User opens Use Case.
2. User selects "Generate Feature".
3. If the Use Case has no Features yet, plugin uses slug `happy-path`. Otherwise plugin prompts the user for a slug.
4. Plugin creates `Specifications/features/<UC-id>-<slug>.feature` (per ADR-0012). Existing Features are never overwritten.
5. Feature is appended to the Use Case's `featureFiles` list and back-references the Use Case in its frontmatter.

## Postconditions

- A new Feature specification exists under the Use Case.
- The Use Case's `featureFiles` array contains the new path.

## Domain Events

Emitted in the order they occur during the success scenario; see the [Event Catalog](../architecture/Event%20Catalog.md) for payload shapes.

- `specification.created`
- `specification.linkedToUseCase`
