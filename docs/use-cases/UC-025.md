# UC-025 Run a single Scenario from a Use Case

> Run one scenario from the Use Case detail view for a seconds-long feedback
> loop.

- **Domain:** Execution
- **Primary Actor:** Developer
- **Epic:** [[EPIC-013]] — Playwright-Native Runner
- **Stories:** [[US-053]], [[US-056]] (Scenario Reference)
- **Owning Service:** to be assigned at acceptance

## Preconditions

- Test Hub initialized; the playwright-bdd runner is in place ([[US-051]]).
- The Use Case links a Feature with at least one scenario.
- No other Test Run is active (ADR-0018).

## Main Success Scenario

1. Developer opens the Use Case detail view.
2. Developer selects "Run" on a scenario row.
3. Plugin resolves the scenario's Scenario Reference.
4. Plugin starts a Test Run scoped to that single scenario.
5. Test Console streams output for the run.
6. Plugin imports the report and generates Evidence with scope `scenario`.
7. The scenario row reflects the new result.

## Extensions

- **4a. Another run is active:** plugin refuses the start and offers to
  cancel the active run (ADR-0018 single-run semantics).
- **6a. Scenario fails:** Evidence links the trace; Developer continues
  with [[UC-026]].

## Postconditions

- A scenario-scoped run is recorded; Evidence and per-scenario history
  ([[US-057]]) are updated.
- Re-running from the result preserves the scenario scope.

## Domain Events

The existing run/report/evidence families are reused with the new
`scenario` scope; payload shapes follow the [Event Catalog](../architecture/Event%20Catalog.md)
and are finalized with the EPIC-013/014 ADRs.

- `testrun.started` *(scope: scenario)*
- `testrun.completed`
- `report.imported`
- `evidence.generated`
