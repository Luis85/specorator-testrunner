# UC-026 Debug a failed Scenario via Playwright trace

> Open a failed scenario's trace in the Playwright trace viewer (or UI mode)
> directly from the Test Hub.

- **Domain:** Execution
- **Primary Actor:** Developer
- **Epic:** [[EPIC-013]] — Playwright-Native Runner
- **Stories:** [[US-080]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- A run executed on the playwright-bdd runner with trace retention enabled
  has at least one failed scenario.
- The trace artifact exists under `.testrunner/reports/`.

## Main Success Scenario

1. Developer opens the Evidence note (or the failure triage view,
   [[UC-029]]) for the red run.
2. Developer selects "Open trace viewer" on a failed scenario.
3. Plugin launches the trace viewer with the scenario's `trace.zip`
   (subject to `CommandSafetyPolicy`).
4. Developer inspects actions, DOM snapshots, console, and network in the
   trace viewer.
5. Developer fixes the step or the SUT and re-runs the scenario
   ([[UC-025]]).

## Extensions

- **2a. Developer wants live debugging instead:** Test Console toolbar
  offers "UI mode", spawning `playwright test --ui` scoped to the current
  target.
- **3a. Trace artifact is absent** (retention swept, trace disabled):
  plugin shows the documented fallback message instead of a broken launch.

## Postconditions

- No vault state changes from viewing a trace; any re-run records normally
  per [[UC-025]].

## Domain Events

No new domain events: launching external tooling is command execution, and
a subsequent re-run emits the standard `testrun.*` family.
