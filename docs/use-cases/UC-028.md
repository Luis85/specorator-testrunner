# UC-028 Review and quarantine a flaky Scenario

> Review a scenario's stability score and move it into a quarantine workflow
> with owner and fix-by date.

- **Domain:** Quality
- **Primary Actor:** QA Engineer
- **Epic:** [[EPIC-014]] — Scenario Identity, History & Flakiness
- **Stories:** [[US-058]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- Per-scenario history ([[US-057]]) has enough depth to compute a stability
  score.
- The dashboard flags at least one scenario as flaky (status flips,
  retry-passes).

## Main Success Scenario

1. QA Engineer opens the flagged scenario from the dashboard.
2. Plugin shows the stability score and the flip/retry history behind it.
3. QA Engineer selects "Quarantine".
4. Plugin tags the scenario `@quarantine` and creates a quarantine note
   recording owner and fix-by date.
5. KPIs exclude the scenario (like `@wip`); suites still run it.
6. Dashboard shows the quarantined count and the oldest deadline.

## Extensions

- **3a. Quarantined share exceeds the cap** (default 5% of scenarios):
  plugin raises a warning — quarantine is a workflow, not a landfill.
- **6a. The fix lands and the scenario stabilizes:** QA Engineer
  unquarantines; the scenario re-enters KPIs.

## Postconditions

- The scenario keeps running and accruing history, but no longer erodes
  KPI trust; ownership and deadline are durable in the quarantine note.

## Domain Events

Proposed (finalized with the EPIC-014 ADR):

- `scenario.quarantined`
- `scenario.unquarantined`
