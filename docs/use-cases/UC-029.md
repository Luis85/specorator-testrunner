# UC-029 Triage a failed run by error group

> Work through a red run with failures grouped by normalized error signature
> instead of row by row.

- **Domain:** Quality
- **Primary Actor:** QA Engineer
- **Epic:** [[EPIC-014]] — Scenario Identity, History & Flakiness
- **Stories:** [[US-059]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- A completed run has multiple failed scenarios.
- Report import attributed failures per scenario ([[US-056]]).

## Main Success Scenario

1. QA Engineer opens the failure triage view for the red run.
2. Plugin groups failed scenarios by normalized error signature — one root
   cause is one group, not fifty rows.
3. QA Engineer expands a group and sees its scenarios, screenshots, and
   trace links.
4. QA Engineer opens a trace for a representative scenario ([[UC-026]]).
5. QA Engineer resolves the group: a fix, a quarantine ([[UC-028]]), or a
   defect note.
6. The Evidence note carries the same grouping for the durable record.

## Extensions

- **2a. An error doesn't normalize** (unique signature per scenario): it
  forms its own group — grouping degrades gracefully to the flat list.

## Postconditions

- Triage outcome is recorded where it belongs (fix in the repo, quarantine
  note, or defect note); the Evidence note reflects the grouped view.

## Domain Events

No new domain events required: the view derives from imported results;
follow-up actions emit their own families (`scenario.quarantined`,
re-run `testrun.*`).
