# UC-030 Generate the traceability matrix

> Generate the requirement→feature→scenario→latest-result matrix note that
> answers coverage and audit questions with one artifact.

- **Domain:** Requirements
- **Primary Actor:** Delivery Manager
- **Epic:** [[EPIC-015]] — Audit-Grade Evidence & Release Readiness
- **Stories:** [[US-061]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- Use Cases link Features; scenarios have identities ([[US-056]]) and
  latest results in history ([[US-057]]).

## Main Success Scenario

1. Delivery Manager selects "Generate traceability matrix" (command or
   dashboard action).
2. Plugin walks the link graph: Use Case → Feature → scenario → latest
   result.
3. Plugin writes the matrix as a Markdown table note — derived purely from
   links/frontmatter, never hand-maintained.
4. Uncovered Use Cases and orphan Features are listed explicitly.
5. Delivery Manager reviews the matrix and commits it with the vault.

## Extensions

- **2a. A link target is broken:** the matrix lists it as a defect of the
  graph instead of silently skipping it (same rule set the headless CLI
  [[US-096]] enforces in CI).

## Postconditions

- Matrix note regenerated idempotently and diff-friendly: re-running
  without underlying changes produces no diff.

## Domain Events

Proposed (finalized with the EPIC-015 work):

- `traceability.matrixGenerated`
