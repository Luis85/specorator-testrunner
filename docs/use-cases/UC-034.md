# UC-034 Drive the Test Hub from a coding agent via MCP

> A user-owned coding agent authors specs, implements steps, runs scopes, and
> triages failures through the opt-in local MCP server.

- **Domain:** Automation
- **Primary Actor:** Developer (via their own coding agent — Claude Code,
  Copilot, …)
- **Epic:** [[EPIC-016]] — Agent Integration via Local MCP
- **Stories:** [[US-067]], [[US-068]], [[US-069]], [[US-070]], [[US-071]],
  [[US-089]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- The MCP server is activated explicitly in settings (**off by default**).
- The Developer's agent is configured against the stdio server; optionally
  the provider-rendered agent skills ([[US-089]]) and generated context
  ([[US-068]]) are installed.

## Main Success Scenario

1. Developer asks their agent to verify a feature against the SUT.
2. Agent lists and reads Use Cases, Features, and Suites through MCP tools.
3. Agent validates the target Feature and detects missing steps.
4. Agent writes typed step-definition drafts (mutations restricted to the
   vault's testing folders by the path-safety policy).
5. Agent runs the scope (suite, feature, or scenario) and fetches results.
6. On failure, agent pulls the failing-scenario bundle (error, step code,
   trace path) and proposes a patch as a reviewable diff.
7. Developer reviews, accepts the diff, and the loop repeats until green.

## Extensions

- **4a. Tool call targets a path outside the testing folders:** denied by
  the path-safety policy.
- **5a. Another run is active:** ADR-0018 single-run semantics apply; the
  tool returns the refusal rather than queueing.
- **6a. The patch would change `.feature` business wording:** requires
  explicit confirmation — healing fixes glue, not requirements.
- **\*a. Obsidian isn't running** (CI/agent use): the server generated into
  `.testrunner` works standalone.

## Postconditions

- All agent-authored content exists as reviewable drafts/diffs or
  explicitly labeled note sections — nothing auto-committed; deterministic
  tests remain the output.

## Domain Events

No new event families: MCP tools call the same service layer a human does,
so the standard `testrun.*`, `report.*`, and `evidence.*` events fire.
Server lifecycle events are decided with the EPIC-016 ADR.
