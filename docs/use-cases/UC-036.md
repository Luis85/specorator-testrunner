# UC-036 Promote a checklist item to an automated Scenario

> Grow from a Markdown checklist into BDD gradually by promoting individual
> checklist items to scenarios.

- **Domain:** Specifications
- **Primary Actor:** Solo Developer
- **Epic:** [[EPIC-017]] — Discovery & Non-Technical Collaboration
- **Stories:** [[US-075]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- A checklist note created from the template exists (e.g. a pre-launch
  list).

## Main Success Scenario

1. Solo Developer works the checklist, recording manual pass/fail per item
   (captured as manual results in evidence).
2. For an item worth automating, Solo Developer selects "Promote to
   scenario".
3. Plugin appends a draft scenario to the chosen Use Case's feature; the
   item keeps a link to its origin.
4. Solo Developer implements the steps (or lets an agent do it, [[UC-034]]).
5. When the promoted scenario first passes, the originating item auto-ticks
   — reusing the Guided Tour's event-observed checklist infrastructure
   (ADR-0020).

## Extensions

- **2a. No Use Case fits the item yet:** the editor offers to create one
  ([[UC-037]]) before promoting.
- **5a. Reuse of the tour infrastructure proves unsuitable** (the US-075
  evaluation): items tick manually; the auto-tick ships later.

## Postconditions

- Adoption stays gradual: unpromoted items remain valid manual checks with
  recorded results; promoted items join the automated suite without losing
  their provenance.

## Domain Events

Proposed (finalized with the EPIC-017 work):

- `checklist.itemPromoted`
- existing `testrun.*`/`evidence.*` families for the auto-tick observation
