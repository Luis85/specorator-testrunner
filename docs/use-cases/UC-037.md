# UC-037 Author a Use Case with the guided editor (incl. linked Actor notes)

> Create a well-formed Use Case through structured fields, with actors and
> domains as pick-or-create linked entity notes.

- **Domain:** Requirements
- **Primary Actor:** Product Owner
- **Epic:** [[EPIC-017]] — Discovery & Non-Technical Collaboration
- **Stories:** [[US-082]], [[US-083]]
- **Owning Service:** to be assigned at acceptance

## Preconditions

- Test Hub initialized; the focus-preserving editor re-render foundation
  (pre-V2 plan item 1.12 / TD-004) is in place.

## Main Success Scenario

1. Product Owner opens the Use Case Editor.
2. Product Owner fills the structured fields: title, description, domain,
   actor, preconditions, main-success-scenario steps, postconditions,
   linked Features.
3. The actor and domain fields offer pick-or-create autocomplete over
   existing entity notes.
4. Creating inline scaffolds a new entity note with typed frontmatter
   (`type: actor` / `type: domain`) in the dedicated folder.
5. The live validation strip flags gaps (missing title/actor, empty success
   scenario, broken Feature links).
6. Product Owner saves; the note is written in the UC-001 house format.
7. Backlinks now answer "who uses this" and "what belongs to this domain"
   from the entity notes and the graph view.

## Extensions

- **1a. An existing hand-written Use Case doesn't round-trip:** the editor
  falls back to raw mode rather than rewriting user content (the shipped
  Feature Editor pattern).
- **3a. Legacy free-text `actor:`/`domain:` values exist:** the one-shot,
  non-destructive migration command converts them into entity notes +
  links.

## Postconditions

- A well-formed Use Case exists without the author knowing the frontmatter
  schema; all properties stay plain YAML (Bases-queryable per [[US-076]]).

## Domain Events

Existing family, reused:

- `usecase.created` / `usecase.updated`
