## Installation

### UC-001 Initialize Test Hub

- **Goal:** Initialize a fully functional Test Hub inside the current Obsidian vault.
- **Primary Actor:** User
- **Scope:** Mandatory MVP

**Preconditions**

- Obsidian plugin installed.
- Vault opened.

**Main Success Scenario**

1. User opens Test Hub.
2. User selects "Initialize Test Hub".
3. Plugin creates required folder structure.
4. Plugin creates documentation.
5. Plugin creates demo content.
6. Plugin creates default suites (Smoke, Regression).
7. Plugin creates `.testrunner`.
8. Plugin installs dependencies.
9. Plugin validates installation.
10. Dashboard opens.

**Postconditions**

- Test Hub operational.

## SDD mapping

| Use Case domain | Owning service in SDD §10 |
| --- | --- |
| Installation (UC-001) | `InitializationService` + `RunnerInstallationService` |
| Installation (UC-002, UC-020) | `EnvironmentValidationService` |
| Installation (UC-003, UC-024) | `MaintenanceService` |
| Requirements (UC-004, UC-005) | `UseCaseAggregate` via vault adapter |
| Specifications (UC-006, UC-007) | `FeatureAggregate` via vault adapter |
| Suites (UC-008, UC-009) | `SuiteAggregate` (tag expressions, AD-4) |
| Automation (UC-010) | `StepDefinitionService` |
| Execution (UC-011–UC-015) | `TestExecutionService` + `TestRunAggregate` |
| Evidence (UC-016, UC-017) | `ReportImportService` + `EvidenceGenerationService` |
| Dashboard (UC-018) | `DashboardView` over `TraceabilityService` |
| CI/CD (UC-019, UC-020) | `PipelineGenerationService` + `EnvironmentValidationService` |
| Documentation (UC-021–UC-023) | `DocumentationView` over generated `Test Hub` notes |
